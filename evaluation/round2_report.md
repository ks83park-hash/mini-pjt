### 원인 분석 (검색 / 프롬프트 / 도구 / 가드)

**규칙 평가는 40/40(100%)이다. 라운드 1의 2건이 해결됐고 악화된 문항은 없다.**
- 수정으로 귀속할 수 있는 개선은 e31, e36 두 건뿐이다. 두 문항은 이미 본 문항이라 이 통과만으로는 "고쳤다"는 증거가 약해서,
  표현을 바꾼 변형 문장으로 따로 확인했다: 운송장 질문 변형 6개 모두 올바른 도구를 쓰고 운송장 번호를 정확히 답했으며(회귀 없음),
  가드는 개수를 정한 정상 요청 4개를 통과시키고 공격 변형 2개를 계속 막는다 (수정을 끄면 같은 테스트가 실패하는 것도 확인했다).
- **같은 문항을 다시 돌려도 답이 달라진다 (측정의 흔들림).** 정책 질문 12개 중 6개의 답변 문장이 라운드 1과 라운드 2에서 달랐다 (온도 0인데도).
  정책 검색 단계에서 모델이 만드는 검색어가 달라져 검색된 문서가 다른 문항도 있다 (e21, e26).
- **그래서 RAGAS 점수의 변화는 이번 수정의 효과로 볼 수 없다.** faithfulness 평균이 0.833에서 0.931로 올랐지만 정책 질문에는 손대지 않았다.
  오른 것의 대부분은 e26이다: 라운드 1에서는 "도착합니다"라는 표현 때문에 RAGAS가 0.0을 줬고(지표의 지나친 엄격함), 라운드 2에서는 답변 표현이 달라져 1.0이 됐다.
  e23도 0.67에서 1.0으로, 반대로 e05는 0.67에서 0.50으로 움직였다. context precision이 1.0에서 0.944로 내려간 것도 e21(검색된 문서가 달라짐)과 e24의 문항 하나씩에서 온 것이다.
  이 정도의 변동이 있으므로, 한 번의 측정으로 0.1 안팎의 차이는 "개선"이라고 말할 수 없다.
- Judge는 두 라운드 모두 12개 전부 5점이다. 점수가 포화되어 라운드 사이의 차이를 보지 못한다.
- **응답 시간 — 성공 기준 "단순 조회 평균 10초 이내"가 이 라운드에서 미달(11.3초)이다.** 전체 평균은 4.21초, 최대는 63.75초로 라운드 1(2.72초, 8.06초)보다 나빠 보이는데, 문항 하나(e11)가 63.75초 걸린 탓이다.
  단순 조회 7문항 중 이 한 건이 평균을 11.3초로 끌어올렸다 (중앙값은 2.6초).
  그 문항은 서버 처리 63,749ms 중 도구가 4ms라서 모델 호출이 막혔던 것이다 (모델 호출 한도에 걸린 뒤의 재시도로 추정). 이상치를 빼면 평균 2.68초로 라운드 1과 같다.
  수정과 무관하지만, 사용자 한 명에게는 1분 넘는 응답이 나갔다는 점에서 별도 문제다.

3. **평가셋이 포화되었다 (규칙 40/40, Judge 5.0 전부).** 변별력을 위해 더 어려운 문항이 필요하다: 근거가 일부만 있는 질문, 정책과 주문 상태를 함께 따져야 하는 질문,

4. 검색의 노이즈(질문과 무관한 교환·배송 문서가 거리 1.54~1.57로 뒤에 붙음)는 이번에도 답변을 해친 증거가 없어 건드리지 않았다. 검색어가 달라져 근거가 달라지는 문제(e21, e26)는 3의 측정 뒤에 본다.
5. 이 라운드의 결론: 확인된 결함 2개(도구 선택, 가드 오차단)는 고쳤고 회귀는 없다. RAGAS·Judge의 변화는 개선이 아니라 측정의 흔들림이다.
